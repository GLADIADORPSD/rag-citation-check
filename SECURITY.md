# Security policy

## Supported versions

The project has not published a stable version yet. Security fixes currently target the default
branch and the latest prerelease, when one exists.

## Reporting a vulnerability

Do not disclose exploitable details, secrets, private source material, or production data in a
public issue.

Use GitHub's private vulnerability reporting flow from the repository's **Security** tab. If that
flow is unavailable, open a public issue titled `Security contact requested` without technical
details. A private channel will then be arranged before details are shared.

Reports should include the affected version or commit, impact, reproduction conditions, and any
suggested mitigation. Receipt will be acknowledged when the report is reviewed; response and fix
timelines depend on severity and maintainer availability.

## Security boundaries

The package is intended to validate specific, documented citation properties. It does not establish
source authenticity, authority, semantic support, or factual truth, and it must not be used as the
sole control for high-impact decisions.
